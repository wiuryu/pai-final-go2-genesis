# Go2 四脚ロボットを GRU で歩かせる — Genesis（微分可能シミュレータ）で学習

Physical AI 応用1 最終課題。四脚ロボット Unitree Go2 を、物理シミュレータ [Genesis](https://github.com/Genesis-Embodied-AI/Genesis) の中で歩かせる。
**GRU が 12 関節の目標角を直接出力**し、**模倣学習 → シミュレータの勾配による微調整**の 2 段階で学習する。

## 課題設定
- 初期ヨー（進行方向）が **±0.6 rad（±34°）ずれた状態**で出発し、ヨーを 0 に戻して **0.5 m/s** で 6 秒間歩く。転ばない。
- GRU への入力は **17 次元の部分観測**（歩容の位相 sin/cos、12 関節角、roll・pitch・yaw）。**速度は与えない**。
- 出力は 12 関節の目標角（HOME からの差）。関節は PD 制御（kp=80, kv=2）。**歩容は出力に足さない**（GRU が最初から学ぶ）。
- 比較対象は「歩容だけ（開ループ）」。

## 方法
1. **段階1: 模倣（`imitate.py`）** 教師 = 手書きトロット歩容 + ヨー P 制御（左右の thigh 振幅に差をつけて曲がる）。DAgger で GRU に模倣させる。
   歩容は探索で決めた値: 2.5 Hz、thigh 0.20 / calf 0.30 / hip 0.10 rad。
2. **段階2: 勾配による微調整（`finetune.py`）** 6 秒を 20 ステップの窓に区切り、窓ごとに `scene.backward(loss)`（truncated BPTT）。
   損失 = ヨー² ・速度誤差² ・横速度² ・roll/pitch² ・高さ ＋ **関節速度²（動きすぎの抑制）・胴体角速度²（頭の振れ）・足の滑り（接地中の足先の水平速度²）・左右非対称**。
   エピソードごとに評価し、最良のものを保存。
3. 足先の位置は関節角からの順運動学で求め（`walker.py: foot_pos`）、微分可能なので滑りも損失に入れられる。

## 結果（学習・選択に一度も使っていない初期条件 9001, 9002, 9003 × 16 体）
| 指標 | 歩容のみ（開ループ） | GRU（最終） |
|---|---|---|
| 転倒率 | 0 | 0 |
| ヨー誤差 平均 [rad]（小さいほど良い） | 0.297 | **0.072** |
| ヨー誤差 最後の 2 秒 [rad] | 0.301 | **0.021** |
| 前進速度 [m/s]（目標 0.5） | 0.512 | 0.485 |
| 速度誤差 [m/s] | 0.103 | **0.025** |
| 終了時の横ずれ \|y\| [m] | 0.512 | **0.156** |
| 関節速度 RMS [rad/s] | 2.65 | **1.64** |
| 胴体の角速度 RMS [rad/s] | 1.31 | **0.69** |
| 足の滑り [m/s] | 0.468 | **0.166** |
| 左右非対称 | 0.013 | 0.022 |

- ヨーは最終的に 0 付近へ戻り（最後の 2 秒で約 1°）、直進する。開ループは最後までずれたまま。
- 学習は 1 回の seed の結果（モデル選択は seed 0〜3 の中から評価用 seed の総合スコアで選んだ → 評価用 seed の数値はやや楽観的。上の表は未使用の seed で再評価したもの）。

### 性能を上げるために試したこと（`results/tuning_log.md`）
段階2 のエピソード数（探索では 40 まで回した。最良はいずれも 7〜24 エピソード目）・学習率・環境数・損失の重みを変えた。**どれも頭打ち**で、総合スコア 0.453 → 0.381〜0.43 の範囲（約 5〜15% 改善）。
最も効いたのは前進速度の重み（30 → 100）で、速度誤差が 0.045 → 0.025 に下がった。滑りの重みを上げると他の指標が悪化した。

## 応用: 経路上の点を順に通過する（再学習なし）
GRU は「ヨーを 0 に戻す」ように学習してある。入力のヨーを「目標方向とのずれ」に置き換えると、GRU は目標方向へ向きを変えて歩く。
目標方向は、現在位置から次の点へ向かう方向とした。点の 0.4 m 以内に入ったら通過とみなす（`waypoints.py`）。

| モデル | 元の経路（8 点） | 左右反転（8 点） | 大きく蛇行（6 点） |
|---|---|---|---|
| 学習段階 2（最終） | 8 点すべて通過 | 8 点すべて通過 | 6 点すべて通過 |
| 学習段階 1（模倣のみ） | 1 点 | 0 点 | 0 点 |

模倣のみでは操舵が弱く、点に届かなかった。それぞれ 1 回の実行（結果は決定的）。

## 限界・失敗（正直に）
- **勾配は短い窓でしか使えない**: 自動微分と有限差分の一致は 20 ステップ以内。40 ステップ超では接触のため信頼できない。
- **勾配による微調整は長く続けると不安定になる**: 最良は 16 エピソード目で、その後は性能が乱高下し、30 エピソード付近では転倒が増え、40 エピソード目には全員が転ぶ（ヨー 1.2 rad）。エピソードごとに評価して最良を保存しているので結果には影響しないが、**早期終了（最良の保存）が必須**。学習率や環境数を変えても、最良は 7〜24 エピソード目で頭打ちだった。
- **勾配だけで最初から学習すると崩れる**（探索段階で確認）。そのため模倣で初期化している。
- **GRU の記憶は必須ではない**: 探索段階では、同サイズの MLP と GRU の差は測定ノイズ内だった。教師は現在の姿勢だけでほぼ決まるため。
- 微調整で GRU の出力は教師から離れる（thigh の目標角の相関 0.25）。歩行指標は良いが、教師の再現ではなく別の歩き方になっている。
- 胴体の揺れ（角速度）と足の滑りは、手書き歩容の運動学に大きく依存する。損失だけでは直らず、歩容パラメータの探索で大きく下がった。
- 結果は 1 つの歩容設定・シミュレータ上のみ。実機での検証はしていない。
- 上記の「探索段階」の実験コード（歩容探索・MLP との比較・勾配検証など）はこのリポジトリには含めていない。

## 再現手順
```bash
pip install -r requirements.txt     # genesis-world, torch, numpy, matplotlib。動画には ffmpeg も必要
./run_all.sh                        # CPU で十数分。models/ results/ と動画 2 本が出る
```
個別に実行する場合:
```bash
python imitate.py --seed 2 --out results/imitate.pt
python finetune.py --init results/imitate.pt --seed 2 --episodes 20 --w vx=100 --out models/gru_final.pt
python baseline.py --ckpt models/gru_final.pt --seeds 9001 9002 9003
python video.py compare --ckpt models/gru_final.pt
python video.py inside  --ckpt models/gru_final.pt
python video.py summary --ckpt models/gru_final.pt --ckpt1 results/imitate_final.pt   # タイトル画面つきのまとめ動画（約 104 秒）
python waypoints.py                 # 経路上の点を順に通過するタスク（再学習なし）の評価
```
同梱の `models/gru_final.pt`（約 20 KB）は上の表のモデル。`run_all.sh` は同じ設定（seed 2）で一から学習するが、CPU の並列実行や環境の差で結果は多少異なりうる。

## ファイル
| ファイル | 内容 |
|---|---|
| `walker.py` | 環境・歩容・観測・GRU・損失・評価（共通部品） |
| `imitate.py` | 段階1: DAgger による模倣 |
| `finetune.py` | 段階2: シミュレータの勾配による微調整 |
| `baseline.py` | 開ループ歩容との比較指標 |
| `video.py` | 動画（開ループとの比較 / GRU の内部の可視化 / まとめ動画） |
| `waypoints.py` | 学習済み GRU を、経路上の点を順に通過するタスクに流用する |
| `models/gru_final.pt` | 最終モデル |
| `results/` | 指標の JSON・チューニングログ |
